# KOZO v1.0.1

KOZO v1.0.1 is a focused build-tooling patch for the governed kernel
foundation. It fixes cross-host Odin object-output handling without changing
the kernel runtime, ABI, fixed user boundary, marker sequence, or terminal
halt behavior.

## What Changed

Odin may emit an object at the exact requested path, append `.o`, or use the
accepted legacy `.obj` form. The build helper now recognizes those exact
possibilities and normalizes one current compiler output to the canonical path.

The helper removes known stale candidates before compilation and fails when
output is missing, ambiguous, a symlink, or not a regular file. It preserves a
nonzero compiler exit status and does not scan for arbitrary object files.

## Why This Patch Matters

The v1.0.0 source build assumed one Odin filename behavior. A newer Odin build
emitted an appended `.o`, causing the release-bundle build to fail even though
the compiler produced a valid x86-64 object. This patch keeps that compiler
variation inside one explicit build boundary.

## Runtime Preservation

The accepted release gate remains:

* 67 verification checks with zero failures;
* QEMU outcome `pass` with blocker `none`;
* 41 ordered runtime markers;
* final marker `KOZO_RUNTIME_RETURN_OK`.

No kernel or userspace runtime source changed for this patch.

## Download And Verify

Download the six release assets into an empty directory:

```bash
gh release download v1.0.1 \
  --repo irgordon/kozo \
  --dir .
```

Verify every downloaded asset:

```bash
shasum -a 256 -c SHA256SUMS
```

Use `sha256sum -c SHA256SUMS` on systems that provide GNU coreutils.

## How To Run It

From a KOZO source checkout, point the governed QEMU smoke script at the
downloaded ISO:

```bash
KOZO_BOOT_ISO="/absolute/path/to/kozo.iso" scripts/qemu_smoke.sh
```

A successful run reports QEMU outcome `pass`, blocker `none`, and final marker
`KOZO_RUNTIME_RETURN_OK`. The runtime then enters its terminal halt loop; it
does not provide an interactive prompt.

## Current Limits

KOZO v1.0.1 remains the same scoped kernel foundation as v1.0.0. It does not
provide a desktop, shell, scheduler, persistent processes, general userspace,
a general syscall interface, filesystem, drivers, networking, Linux or POSIX
compatibility, hostile user-code containment, or a stable public ABI.

## Release Integrity

The published `v1.0.0` and `v1.0.0-rc.1` tags, notes, and assets remain
immutable. This patch is a new release record and does not repair either
earlier release in place.
