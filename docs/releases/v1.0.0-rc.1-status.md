# KOZO v1.0.0-rc.1 Status

## Current Status

KOZO `v1.0.0-rc.1` is published as a
[GitHub prerelease](https://github.com/irgordon/kozo/releases/tag/v1.0.0-rc.1)
for testing and review. It is not the final v1.0.0 release and is not
production-ready.

Post-promotion verification downloaded the hosted files again, validated their
checksums and metadata, booted the hosted ISO in QEMU, and inspected the hosted
kernel ELF. The distributed runtime produced all 41 accepted markers in order
and ended with `KOZO_RUNTIME_RETURN_OK`.

## How to Download

```bash
mkdir kozo-v1.0.0-rc.1
cd kozo-v1.0.0-rc.1
gh release download v1.0.0-rc.1 \
  --repo irgordon/kozo \
  --dir .
```

The same files are available from the
[GitHub prerelease page](https://github.com/irgordon/kozo/releases/tag/v1.0.0-rc.1).

## How to Verify Checksums

From the download directory:

```bash
shasum -a 256 -c SHA256SUMS
```

Every listed file must report `OK`.

## How to Run the ISO

From a KOZO source checkout, point the existing smoke script at the downloaded
ISO:

```bash
KOZO_BOOT_ISO="/absolute/path/to/kozo.iso" scripts/qemu_smoke.sh
```

The script applies the governed timeout, captures serial and stderr output, and
classifies missing evidence.

## Expected Result

A successful run reports:

```text
Outcome: pass
Blocker: none
Expected Marker: KOZO_RUNTIME_RETURN_OK
```

The serial log contains 41 ordered markers and ends with
`KOZO_RUNTIME_RETURN_OK`. KOZO then remains in its terminal halt loop.

## Known Limits

This prerelease proves the current bounded kernel foundation. It does not
provide a desktop, shell, scheduler, process model, filesystem, device stack,
networking, general userspace, Linux or POSIX compatibility, hostile-code
containment, or production readiness.

## Dry-Run Metadata Explanation

The GitHub prerelease is published and available for testing.
`release_metadata.json` still contains `"published": false` because the bundle
was created and validated as a dry run before promotion. The same validated
bundle was later uploaded to GitHub without rebuilding or changing it.

## Reported Defects

No runtime or hosted-artifact defect was reproduced during post-promotion
verification. The clean-clone documentation check exposed one command issue:
the LLVM linker version check must use `ld.lld --version`, not the generic
`lld --version` driver. The user guide now uses the working command.

## Final-Release Blockers

No reproducible blocker was found during this phase. Final v1.0.0 promotion
still requires explicit authorization.
