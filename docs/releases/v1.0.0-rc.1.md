# KOZO v1.0.0-rc.1

This is a release candidate.

It is a complete test of the current release process, artifacts, evidence,
licenses, and documentation. It is not the final production release.

## Why This Release Matters

KOZO now has a reviewable path from a clean commit to a bootable image, kernel
ELF, generated verification evidence, legal files, release metadata, checksums,
and an inspected dry-run archive.

## What Works

The accepted runtime boots through Limine, establishes its governed CPU and
memory prerequisites, executes one fixed Ring 3 transaction, runs the bounded
Odin runtime path and two fixed internal capabilities, returns to assembly, and
enters the terminal halt loop.

## What Is Proven

The release gate requires 67 passing verification checks, QEMU outcome `pass`,
blocker `none`, and all 41 ordered runtime markers. The bundle builder rejects
missing evidence, missing legal files, version drift, dirty source state, and
prohibited archive paths.

## How To Run It

Follow [Getting Started](../wiki/GETTING_STARTED.md) to install the pinned
toolchains, build the image, and run the governed QEMU smoke command.

## How To Verify It

Run the commands in [Validation](../VALIDATION.md). Build the dry-run archive
from a clean commit:

```bash
scripts/build_release_candidate.sh \
  --version 1.0.0-rc.1 \
  --output /tmp/kozo-release-candidate
```

Then validate `/tmp/kozo-release-candidate/SHA256SUMS` and inspect the archive
directly.

## Known Limits

This candidate does not claim a stable public ABI, general userspace, a general
syscall interface, process or scheduler behavior, dynamic or general virtual
memory, device or network support, Linux or POSIX compatibility, hostile-code
containment, complete exception recovery, multicore execution, or production
readiness.

The fixed Ring 3 path is a boot-time probe in one address space. It is not a
general user process.

## Known Warnings

Hosted CI confirmed the official Node 24 checkout and artifact actions and the
authenticated Odin setup without the prior warning signatures.

Force pushes to `main` are blocked. This phase added no review requirement,
required status check, administrator enforcement, conversation-resolution
rule, deletion restriction, ruleset, or other repository policy.
