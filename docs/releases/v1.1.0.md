# KOZO v1.1.0

KOZO v1.1.0 extends the governed kernel foundation with a fixed user execution
context and exactly two sequential bounded user sessions. The release remains
small and non-interactive, but now proves that one static Ring 3 execution
boundary can be cleared, checked, and safely reused with a fresh identity.

## What Changed

* Added one supervisor-owned Fixed User Execution Context with an explicit
  lifecycle, opaque kernel identity, validated result, and fail-closed cleanup.
* Added exactly two sequential fixed user sessions through the same context.
* Assigned a distinct kernel-owned identity to each session.
* Validated complete result, buffer, stack, scratch, and phase reset between
  sessions.
* Preserved two `int 0x81` returns per session and four total returns.
* Preserved duplicate marker occurrences so runtime evidence proves both
  complete transactions.

## Why It Matters

The v1.0.1 runtime proved one bounded user transaction. v1.1.0 proves that the
same fixed infrastructure can remove the first session's authority, establish
a fresh bounded session, complete it, and continue the kernel. This is a step
toward longer-running user services without claiming processes or scheduling.

## Runtime Proof

```text
sessions: 2
int 0x81 transitions per session: 2
total int 0x81 transitions: 4
ordered runtime markers: 52
verification: 67 checks, 0 failures
QEMU: pass
blocker: none
final marker: KOZO_RUNTIME_RETURN_OK
```

A third session or fifth transition fails closed. Later internal capabilities
run only after session 2 completes and all execution authority is cleared.

## Portability

Linux is validated for the governed build and QEMU runtime contracts. Windows
2025 under Git Bash and macOS 15 are validated for the build contract only;
their runtime contracts were not executed. Cross-host release-input identity
passes for the governed repository inputs.

## Download And Verify

Download the six release assets into an empty directory:

```bash
gh release download v1.1.0 \
  --repo irgordon/kozo \
  --dir .
```

Verify every covered asset before use:

```bash
shasum -a 256 -c SHA256SUMS
```

Use `sha256sum -c SHA256SUMS` on systems that provide GNU coreutils.

## Run The ISO

From a KOZO source checkout, point the governed smoke script at the downloaded
ISO:

```bash
KOZO_BOOT_ISO="/absolute/path/to/kozo.iso" scripts/qemu_smoke.sh
```

A successful run reports QEMU outcome `pass`, blocker `none`, 52 ordered
marker occurrences, and final marker `KOZO_RUNTIME_RETURN_OK`. KOZO then enters
its terminal halt loop; it does not open a prompt or graphical interface.

## Assets

The GitHub release contains:

* `kozo-v1.1.0.tar.xz`
* `kozo.iso`
* `kozo-kernel.elf`
* `latest_verify.json`
* `release_metadata.json`
* `SHA256SUMS`

Generated `release_metadata.json` records `published: false` because the bundle
is built and accepted before GitHub publication. The later immutable GitHub
release record is the publication authority.

## Current Limits

KOZO v1.1.0 does not provide general processes, a scheduler, dynamic
userspace, a general syscall interface, a filesystem, drivers, networking,
Linux or POSIX compatibility, Windows runtime validation, macOS runtime
validation, hostile user-code containment, or a stable public ABI.
