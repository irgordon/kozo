# KOZO v1.0.0

KOZO v1.0.0 is the first final release of the governed kernel foundation. It
provides a small, auditable kernel path with verified boot, memory, CPU,
paging, user-mode, request, response, and runtime behavior.

This release does not include a desktop, interactive shell, scheduler,
filesystem, drivers, or general-purpose application environment.

## Why This Release Matters

Early kernel failures often happen before normal debugging tools are
available. KOZO keeps the supported path small, emits ordered serial evidence,
and checks the source, linked kernel, QEMU run, contracts, and schemas against
the same declared boundaries.

## What KOZO Solves

KOZO gives learners, maintainers, and reviewers one bounded kernel path that
can be inspected from boot entry through a deterministic terminal halt. Each
success claim is tied to a specific runtime marker and mechanical validator.

## What Is Included

The release includes:

* a bootable x86-64 QEMU ISO;
* the linked x86-64 kernel ELF;
* generated verification evidence;
* release metadata and SHA-256 checksums;
* contracts, schemas, and generated reports;
* user, maintainer, and engineering documentation;
* the MIT and Apache-2.0 repository license texts.

## What Is Proven

The accepted release gate proves:

* governed QEMU boot;
* controlled stack and memory initialization;
* CPU extended-state initialization and a bounded SIMD probe;
* fixed four-level page tables with supervisor and fixed user mappings;
* one bounded Ring 3 transition and governed return;
* one fixed user request, response, and response-consumption path;
* one controlled Odin runtime loop;
* two governed internal runtime capabilities;
* fail-closed terminal halt behavior;
* 67 passing verification checks and 41 ordered runtime markers.

The final marker is `KOZO_RUNTIME_RETURN_OK`.

## How To Download And Verify It

Download the six release assets into an empty directory:

```bash
gh release download v1.0.0 \
  --repo irgordon/kozo \
  --dir .
```

Verify every downloaded asset:

```bash
shasum -a 256 -c SHA256SUMS
```

Use `sha256sum -c SHA256SUMS` on systems that provide GNU coreutils.

## How To Run It

From a KOZO source checkout, point the governed QEMU smoke script at the
downloaded ISO:

```bash
KOZO_BOOT_ISO="/absolute/path/to/kozo.iso" scripts/qemu_smoke.sh
```

The command is bounded by the repository timeout and writes the serial log,
stderr, metadata, and summary under `artifacts/runtime/`.

## Expected Result

A successful run reports:

```text
Outcome: pass
Blocker: none
Expected Marker: KOZO_RUNTIME_RETURN_OK
```

The runtime emits 41 ordered markers and then enters the terminal halt loop.
There is no interactive prompt.

## Current Limits

KOZO v1.0.0 does not provide:

* a desktop, window manager, settings panel, or interactive terminal;
* a general shell or application environment;
* persistent processes, scheduling, or preemption;
* a general syscall or userspace interface;
* a filesystem, drivers, or networking;
* dynamic virtual memory or a general allocator;
* Linux or POSIX compatibility;
* hostile user-code containment;
* a stable public ABI;
* production desktop readiness.

The fixed Ring 3 path is a boot-time probe in one address space. It is not a
general user process.

## Differences From v1.0.0-rc.1

No runtime behavior changed between v1.0.0-rc.1 and v1.0.0.

The final release adds final versioning, release documentation, packaging,
verification, and hosted release records.

The accepted `v1.0.0-rc.1` tag, notes, and assets remain immutable.
